# FORKSY – Architecture & Build Contract

Source spec: `docs/spec-extracted.txt` (text of *FORKSY_SOPs_Requirements_Functions_Overview.pdf*). **Read it first** – section numbers below refer to it.

Monorepo:

```
backend/   NestJS 11 + TypeORM 0.3 + PostgreSQL (API + Socket.IO realtime)   -> http://localhost:4000/api/v1 , docs at /docs
admin/     React 18 (CRA) on the WowDash Bootstrap template                  -> http://localhost:3000
docs/      this file, spec text, docs/api/<module>.md (one per backend module)
```

Mobile / tablet apps are **out of scope** – the backend exposes complete REST + WebSocket APIs for them.

## 1. Runtime facts

* A local PostgreSQL 18 is running on `localhost:5432` (user/pass `postgres`/`postgres`, UTF-8). Main DB `forksy`.
  Every agent may create **its own scratch database** with `node scripts/create-db.js forksy_<yourmodule>` (inside `backend/`) and boot the app with
  `DB_NAME=forksy_<yourmodule> PORT=41xx npx ts-node --transpile-only src/main.ts` (choose a unique port 4101-4199). Never use DB `forksy` or port 4000 – those belong to the integrator.
  `DB_SYNC=true` (default) auto-creates tables from entities.
* Typecheck: `cd backend && npx tsc --noEmit -p tsconfig.json`. Other agents work in parallel, so errors in files you did not write may appear transiently – only fix your own files.
* No Docker, no psql. Use Node scripts (`pg` package is installed) if you need SQL access.
* Node 24, npm 11. Windows + Git Bash: use forward slashes; write files with the Write/Edit tools (heredocs with apostrophes break).

## 2. Backend conventions (already implemented – reuse, do not reinvent)

| Concern | Where | Notes |
|---|---|---|
| Entities | `src/database/entities/*.entities.ts` | ~75 entities, UUID PKs, `createdAt/updatedAt`. Money = `numeric(12,2)` mapped to JS `number` (CAD dollars). `ALL_ENTITIES` is auto-collected. **Additive edits only** (new nullable/defaulted columns, new entity classes appended at end of a file) – never rename/remove. List every change in your final report. |
| Enums | `src/common/enums.ts` | statuses, roles, modules/actions… additive edits only. |
| Contracts | `src/common/contracts.ts` | service interfaces + domain events. Implement what you own **exactly**; consume others via their class. |
| Auth | global guards in `src/common/guards.ts` | Every route needs JWT unless `@Public()`. |
| Route decorators | `src/common/decorators.ts` | `@AdminController('x')` → `/api/v1/admin/x`, `@RestaurantController('x')` → `/restaurant/x`, `@DriverController('x')` → `/driver/x`, `@CustomerController('x')` → `/customer/x`, `@PublicController('x')` → `/public/x`. Staff permission: `@Permission(Module.ORDERS, Action.EDIT)` (SUPER_ADMIN bypasses). `@RestaurantRoles(...)` restricts restaurant users. `@CurrentUser()` gives `AuthUser` (see `auth.types.ts`: `driverId`, `merchantId`, `restaurantIds`, `restaurantRole`, `permissions`, `refundLimit`…). |
| Pagination | `src/common/pagination.ts` | list endpoints: `GET ?page&limit&search&sortBy&sortDir&<filters>` → `{ data: T[], meta: { page, limit, total, totalPages } }`. Use `PageQueryDto`, `paginateQb`, `like`. |
| Errors | `AllExceptionsFilter` | `{ statusCode, message, details? }`. Throw Nest `HttpException`s. |
| Audit | `AuditService` (global) | `audit.logReq(req, 'restaurant.approve', 'restaurant', id, before, after)` for every sensitive admin action. A global interceptor also logs every mutating staff/restaurant request. |
| Settings | `SettingsService` (global) | `settings.get('orders.autoRejectSeconds', 180)`; all keys/defaults in `src/settings/settings.service.ts` (`SETTING_DEFINITIONS`). Add new keys there (additive). |
| Notifications | `NotificationsService` (global) | `notify({userId, audience, event, vars, data})`, `notifyRestaurant(restaurantId, event, vars)`, `notifyOps(event, vars)`. Events, default copy and channel matrix: `notifications.service.ts` (`DEFAULT_MESSAGES`) + setting `notifications.matrix`. Add events additively. Shared inbox endpoints already exist at `/notifications`. |
| Realtime | `RealtimeService` (global) | `emitToUser/Order/Restaurant/Driver/Zone/Ops(...)`. Rooms + event names documented at top of `src/realtime/realtime.module.ts`. |
| Availability / geo / codes | `AvailabilityService`, `GeoService`, `CodesService` (global, `src/core/core.module.ts`) | open/closed & scheduling slots, zone resolution from lat/lng, order/ticket/invoice codes. |
| Geo math | `src/common/geo.util.ts` | `haversineKm`, `roadEstimate`, `pointInPolygon`, `haversineSql`. |
| Events | `@nestjs/event-emitter` (global) | Constants + payloads in `contracts.ts` (`Events.*`). Use for cross-module reactions (never call a listener module directly). |
| Uploads | `POST /api/v1/uploads` (multipart `file`) → `{url}` | UploadsService; store returned URL strings on entities. |
| Schedulers | `@nestjs/schedule` (`@Cron`, `@Interval`) | keep jobs idempotent & wrapped in try/catch. |
| Users | `User` entity (one identity table). Types: `SUPER_ADMIN, STAFF, RESTAURANT, DRIVER, CUSTOMER`. Customers: `customerId` = `users.id`. Drivers: order/offer `driverId` = **DriverProfile.id**. Restaurants: money party id = **merchantId**; operational id = restaurant (location) id. |
| Auth service | `AuthService` | `completeLogin(user, ctx)` issues tokens; `hash(pw)`; `normalizePhone`. Login/2FA/OTP/registration endpoints already exist under `/auth/*` (customer register, social, driver register, restaurant apply). |
| Staff / roles | `src/staff/staff.module.ts` | done: `/admin/staff`, `/admin/roles` (9 default roles + Support Supervisor). |
| Audit log API | `GET /admin/audit-logs` | done. |
| Settings API | `/admin/settings`, `/admin/settings/feature-flags`, `/admin/settings/app-versions`, `GET /public/config` | done. |

Code style: TypeScript, Nest modules per domain, DTO classes with `class-validator`, `@ApiTags` via the decorators above, thin controllers + services, no `any` where a type is easy, comments only for non-obvious rules (cite the spec section for business rules). Keep files < ~600 lines; split services when needed.

Each module folder: `src/<module>/<module>.module.ts` (exports class `<Module>Module`), `<module>.seed.ts` (exports `seed<Module>(ds, opts)` – **idempotent**, see §5), plus controllers/services/dto.
Modules whose services must be injectable from other modules are decorated `@Global()`.

## 4. API documentation deliverable (mandatory)

When done, each agent writes `docs/api/<module>.md`: a table per controller with **METHOD path – permission/role – query/body fields – response shape** (concise but complete; the React agents build the UI from this alone). Include enums/values the UI needs for dropdowns and any realtime events.

## 5. Seeds

`src/database/seed.ts` runs (in order): core (super admin + 9 demo staff) → platform → marketing → restaurants → drivers → customers → orders → support → finance.
* Each `seed<Module>(ds, opts)` must be **idempotent** (look up by natural key before insert) and respect `opts.demo` (foundational data such as cities/zones/tiers/tax/cuisines/CMS always; demo people & orders only when `opts.demo`).
* Demo passwords: `opts.demoPassword` (default `Demo@12345`) for every demo account; use `bcryptjs` (`bcrypt.hash(pw, 10)`).
* Deterministic demo logins (so docs/README can list them): restaurants `owner1@demo-restaurant.ca` … (OWNER of merchant 1), `manager1@…`, `cashier1@…`, `kitchen1@…`; drivers `driver1@demo.forksy.ca` (phone `+14165550101` …); customers `customer1@demo.forksy.ca` (phone `+14165550201` …). Downstream seeds look records up by these emails/names – keep them stable.
* Run: `cd backend && npm run seed` (needs DB up; boots a Nest context).
* Ontario/Mississauga geography: centre ≈ 43.5890, −79.6441. Postal codes L4Z…L5N range, phone `+1416555xxxx`.
